# DropZone — Decisions Log

Decisions made during implementation are recorded here when a requirement was ambiguous, a browser API behaved differently than specified, or a tradeoff was chosen.

| Date | Phase | Decision | Rationale |
|------|-------|----------|-----------|
| 2026-10-17 | 0 | Added root `eslint.config.mjs` (flat config, `typescript-eslint` recommended); Phase 0 shipped without one, so `pnpm lint` failed the gate. | AGENTS.md requires a passing lint gate; flat config is the ESLint 9 standard. |
| 2026-10-17 | 0 | `@types/node`-style tooling pinned: root devDeps got `@eslint/js@^9` (not v10) to match installed `eslint@9`. | Avoid breaking peer ranges. |
| 2026-10-17 | 1 | Phases 0–1 were uncommitted; committed retroactively as `chore(phase-0)` + `feat(phase-1)` before Phase 2. | AGENTS.md requires a commit per phase. |
| 2026-10-17 | 1 | Protocol `build` script added (`tsc`) and `@vitest/coverage-v8@^3` added to protocol + signaling. | Composite project references need `packages/protocol/dist/*.d.ts` for `tsc` in consuming apps; coverage gate (≥80%) needs the provider. |
| 2026-10-17 | 2 | **Ack envelope convention:** every handler ack returns either the success payload (per protocol `*Ack` schema) or `{ error: { code, message } }` (`ProtocolErrorSchema`, added to `errors.ts`). | TRD §5 defines success acks but not the error transport; Socket.IO acks carry a single value, so an envelope is the least ambiguous shape. |
| 2026-10-17 | 2 | **Approval notification:** on `room:approve allow` the server sends the joiner a self `peer:joined`, then `peer:joined` replay for each existing member, then `ice:refresh`; on deny it sends `room:closed {reason:'JOIN_DENIED'}` to that socket only. | TRD §5 lists no `join:approved`/`join:denied` events; this satisfies FR-07 using only declared protocol events. Self `peer:joined` is unambiguous (deviceId match). |
| 2026-10-17 | 2 | **Added `room:close` client event** to `packages/protocol` (`RoomClosePayloadSchema`, host-only, ack `{}`). | FR-06 (P0) says "host can close room"; no such event existed in protocol/TRD §5. Protocol is the single source of truth, so the gap was fixed there. |
| 2026-10-17 | 2 | **Host migration:** when the host leaves or disconnects, the earliest-joined remaining peer becomes host. | TRD §4 defines `hostDeviceId` but no migration; without it, approval/regenerate/close die with the original host (would break FR-07/08). |
| 2026-10-17 | 2 | **Server factory:** `server.ts` refactored to `createSignalingServer(config)` returning `{app, io, httpServer, store, metrics, close()}`; integration tests bind port 0 and inject `now`, `limitPolicy`, `sweepIntervalMs`. | Top-level `listen(3001)` on import races between test files; injectable clock makes TTL/idle expiry tests deterministic without real waits. `server.ts` remains the thin dev/start bootstrap. |
| 2026-10-17 | 2 | **Pending joiners are not room members:** they get `NOT_IN_ROOM` (not `NOT_HOST`) for host-only events, don't count toward `ROOM_FULL`, but consume join rate-limit tokens. | Matches "waiting outside the room" semantics; avoids an approval-bypass via capacity race. |
| 2026-10-17 | 2 | **Metrics hand-rolled** (`metrics.ts`, Prometheus text format) instead of adding `prom-client`. | Only 6 metrics needed (TRD §18); avoids a new dependency. `METRICS_TOKEN` unset → `/metrics` returns 404 (endpoint disabled). |
| 2026-10-17 | 2 | **Rate-limit constants live in `packages/protocol/src/constants.ts`** (`ROOM_CREATE_RATE_*`, `ROOM_JOIN_RATE_*`, `JOIN_FAIL_*`, `SIGNAL_RATE_*`). | AGENTS.md: constants live in protocol. Limits are overridable per-server via `limitPolicy` (used by tests). |
| 2026-10-17 | 2 | **`RoomStore.closeRoom` leaves peer/pending maps intact** after deregistration so callers can emit `room:closed` before dropping the reference; device→room mappings are cleared so `getByDevice` returns `undefined` post-close. | Notification must know recipients; clearing the registry prevents any further access. |
| 2026-10-17 | 2 | **ICE refresh:** `ctx.admit(socket, deviceId)` schedules a one-shot `ice:refresh` at `TURN expiry − 60 s` (re-armed each time); skipped when no TURN configured. | TRD §5 requires refresh before credential expiry; only sockets in rooms need it. |
| 2026-10-17 | 3 | **`emitAck` binds the timeout socket before `emit`:** `const timed = this.socket.timeout(ACK_TIMEOUT_MS); timed.emit.bind(timed)`. | Calling `this.socket.timeout(ms).emit(...)` in one expression lost `this` on the bound socket, throwing `Cannot read properties of undefined (reading '_opts')`. That exception was swallowed by `callEvent`'s catch and surfaced as `NETWORK`, masking real server errors — the e2e gate failed until this was fixed. Binding to a local restores correct `this` and made `createRoom`/`joinRoom` return real acks. |
| 2026-10-17 | 3 | **`connect()` is awaitable and awaited by `createRoom`/`joinRoom`:** returns a promise resolving on the `connect` event, rejecting after `CONNECT_TIMEOUT_MS` (8 s); caches the promise for idempotency and resets it on failure. | Emitting before the socket connects makes the ack unresolvable. The awaitable connect removes a class of startup races, and the cached promise keeps `createRoom`/`joinRoom` idempotent under React StrictMode double-invokes. |
| 2026-10-17 | 3 | **SignalingClient test mock fires `connect` asynchronously** (`setTimeout(…, 0)`) and `beforeEach` awaits `client.connect()`. | With the awaitable `connect()`, a mock that starts `connected: true` without emitting `connect` leaves the promise pending forever. Async firing mirrors real socket.io (connect is never synchronous) and keeps the gate honest. |
| 2026-10-17 | 4 | **WebRTC outbound signal sender is socket-scoped:** `PeerManager.start(...)` is wired once inside `SignalingClient.connect()`, and `destroyAll()` no longer clears `sendSignal` (it only drops sessions/listeners). | Initially the sender was (re)armed in `createRoom`/`joinRoom` and cleared by `destroyAll()`. Under React StrictMode the Room cleanup runs `destroyAll()` on the double-mount, so the **host's** sender was nulled before the joiner ever arrived: the host created its PC later (on `peer:joined`), its offer/candidates were silently dropped, the joiner (impolite) ignored the glare, and neither side ever answered — both badges stuck on "Online" while signals flowed one-way. B survived only because its offer was sent during `joinRoom`, before the cleanup. Moving wiring to `connect()` makes it socket-lifetime, which is what the sender actually belongs to. |
| 2026-10-17 | 4 | **FR-05 presence stays coarse, FR-30 detail rides on link stats:** `peersStore.presence` is `direct`/`relayed` (FR-05), while `stats.ts` classifies `direct-local`/`direct-internet`/`relayed` (FR-30) and reaches the UI via `PeerManager.subscribeStats` → `PeerCard`'s `linkClass` prop (falls back to the presence label until `getStats()` reports a pair). | FR-05 enumerates five list states; FR-30 requires three exact badge strings from the selected candidate pair. Keeping the store coarse avoids polluting `PeerPresence` with classification detail that only the badge needs, and gives a sensible label during the ≤1 s window before the first stats poll. |
| 2026-10-17 | 4 | **Force-relay debug flag:** `?forceRelay=1` in the URL or `localStorage['dz:forceRelay']='1'` sets `RTCPeerConnection.iceTransportPolicy='relay'`. | Phase 4 gate asks for a debug flag to force relay for later tests; it must survive navigation (localStorage variant) and be settable per-tab via query string. With no TURN server configured yet, enabling it correctly yields no connection — useful for verifying the relay/`offline` paths. |
| 2026-10-18 | 5 | **Preserve transfer engine listeners across `destroyAll`:** In `PeerManager.ts`, `destroyAll()` drops active peer sessions and room-scoped UI listeners (`text`, `rtt`, `stats`), but preserves `controlListeners`, `chunkListeners`, and `sessionRemovedListeners` (along with `sendSignal`). | `TransferHub` is a module-scoped singleton; wiping these listeners on Room unmount broke incoming offers under React StrictMode double-mounts. |
| 2026-10-18 | 5 | **Strict sender isolation on `PeerCard`:** `PeerCard` only renders the file input and "Send file" action when `!isSelf`. | Prevents invalid self-transfers and ensures unambiguous test selector targeting. |
| 2026-10-18 | 5 | **MemoryWriter as Phase 5 storage backend:** Implemented `MemoryWriter` adhering to `ChunkWriter` interface with 500 MB hard cap, positional chunk buffer assembly, and `readSlices` async generator. | Real disk backends (`FsAccessWriter`, `OpfsWriter`) are scheduled for Phase 6 per TRD §10.3; MemoryWriter satisfies basic transfer (FR-10–12). |
| 2026-10-18 | 5 | **Control character sanitization via charCode filtering:** Filtered control characters by checking `code >= 32 && code !== 127` rather than regex. | Satisfies ESLint `no-control-regex` rule while guaranteeing zero ASCII control characters in filenames per TRD §13. |
| 2026-10-18 | 6 | **Storage backend fallback:** When `FsAccessWriter.open()` fails (e.g. user dismisses native file picker or headless Playwright environment), `TransferReceiver` seamlessly falls back to `MemoryWriter` to prevent transfer abort and provide a browser download link. | Robust UX: a dismissed system save dialog shouldn't drop the entire transfer. Enables headless automated testing without OS file dialog dependencies. |
| 2026-10-18 | 6 | **Streaming SHA-256 worker with inline fallback:** SHA-256 is computed concurrently during sending and verified on finalized receiver storage. Worker delegation prevents main-thread blocking; inline `hash-wasm` fallback handles environments without worker support. | Satisfies TRD §11 integrity requirement and keeps UI thread responsive during multi-GB transfers. |
| 2026-10-18 | 6 | **Dual backpressure & bounded prefetch:** TransferSender regulates speed using both SCTP `bufferedAmount` (network) and 16 MiB inflight ACK window (receiver disk), fed by an 8-chunk bounded async `PrefetchQueue`. | Prevents memory blowup on either peer and avoids stalling DataChannels on disk I/O. |
| 2026-10-18 | 6 | **IndexedDB resume bitset:** Resumable chunk state is tracked via `ChunkBitmap` bitsets and persisted to IndexedDB (`dropzone-transfers`) every 64 chunks or 250 ms. | Implements FR-18 and FR-19 without storing transfer state in localStorage. |
| 2026-10-22 | - | **Persistent Room Sessions (No countdown timer expiry while members present):** Removed artificial session countdown and timer-based expiration from the UI and signaling server. Rooms remain open and joinable as long as anyone is in the room (`room.peers.size > 0`). The room closes only when all members leave (`empty`) or the host explicitly closes it. | Requested by user for seamless real-world use without arbitrary room cutoffs during transfers or ongoing work. |
| 2026-10-22 | - | **Wake lock held for the whole occupied-room lifetime, re-acquired on `visibilitychange`:** `wakeLock.ts` is now reference-counted (Room + each active `TransferSender`), and re-requests `screen` whenever the document becomes visible again instead of only during an active transfer. | Root cause of mobile drops: mobile OSes suspend the tab when the screen dims/locks, terminating the WebSocket ~1 s after join. Browsers auto-release the lock on hide and never restore it, so it must be re-requested on return. |
| 2026-10-22 | - | **WebRTC readiness gating before offers:** `TransferHub.sendFiles()` marks a transfer `queued` and waits for `PeerManager.waitForReady()` (channel `open`) before calling `TransferSender.start()`; the wait is bounded by `SEND_READY_TIMEOUT_MS` (30 s) after which the transfer fails with a visible "Could not connect to peer" error. New `PeerSession.isReady()/hasRemoteHello()/attemptRecovery()`, `PeerManager.isReady()/waitForReady()/resumeAll()`. | `PeerSession.sendControl()` returns `true` while the channel is `connecting` (it queues the message), so dispatching an offer into a channel that never opens left the card stuck at `HANDSHAKE… (0B / …)` forever. Gating + a finite timeout converts a silent hang into an actionable error. |
| 2026-10-22 | - | **Tab-resume recovery:** `SignalingClient.resumeFromBackground()` reconnects/re-joins the signaling socket and `PeerManager.resumeAll()` rebuilds dead sessions (or nudges ICE restart) on `visibilitychange` → visible. | The phone was suspended while hidden; on return the signaling socket and/or the WebRTC session may be dead, so both must be revived rather than waiting for a manual refresh. |
| 2026-10-22 | - | **Honest connection-state UI:** `peersStore.presence === 'online'` (signaling-room membership only) now renders as "In room — connecting" (amber) instead of "Online" (green); a new `queued` transfer status renders "WAITING FOR PEER…". | The old label implied the WebRTC path was ready, so users pressed Send before the data channel opened; the label must distinguish "in the room" from "connected". |
| 2026-10-22 | 7 | **Deploy topology: both halves on Render (one Blueprint).** `render.yaml` defines `dropzone-web` (`runtime: static`, publish `apps/web/dist`, SPA rewrite + security headers) and `dropzone-signaling` (Docker web service, free plan, `healthCheckPath: /healthz`). `apps/signaling/Dockerfile` builds with `pnpm --filter signaling deploy --prod --legacy /out` and runs as `USER node`. | TRD §Deployment allows Render for the signaling server; the web app is pure static output, and a Render static site is always free and never sleeps, so one platform covers both. The previous Dockerfile could not build (it ran `pnpm install --prod --frozen-lockfile` against a partial workspace, which fails on pnpm 10) and hardcoded `PORT=3001`, colliding with the `PORT` Render injects. |
| 2026-10-22 | 7 | **Cross-service wiring via `fromService`, with the client normalizing a scheme-less host.** `dropzone-web`'s `VITE_SIGNALING_URL` is `fromService: {name: dropzone-signaling, type: web, property: host}`, which Render resolves to a bare hostname; `getSignalingUrl()` prepends `https://` when the configured value has no scheme. `CORS_ORIGINS` is set to `*` rather than a `fromService` host. | Blueprint `envVars` support no string interpolation, so a bare `host` is the only fully automatic way to point the SPA at the server — but `https://<bare-host>` is not a valid URL, and `origin` checks need a scheme. Normalizing in the client keeps the reference usable in both. `CORS_ORIGINS` is `*` because the server's callback accepts every origin regardless (see the entry below), so a precise-looking value would be misleading. |
| 2026-10-22 | 7 | **Cold starts tolerated instead of surfaced as errors.** `CONNECT_TIMEOUT_MS` is 8 s on a local origin and 95 s otherwise, and the `connect_error` → reject handler was removed so socket.io's own retries can land. | A Render free service spends ~60 s spinning up after 15 min idle. The old code rejected on the *first* `connect_error`, which is exactly what a cold host emits, turning a recoverable wait into an instant `NETWORK` error even though socket.io was still retrying. `reconnection: true` was already configured, so the fix is to let it finish. |
| 2026-10-22 | 7 | **`STUN_URLS` is declared with an explicit value in `render.yaml` instead of `sync: false`.** | The value was previously left to a dashboard prompt, where "leave blank" would set `STUN_URLS=""`. `z.string().default(...)` in `apps/signaling/src/config.ts` only applies when the variable is *undefined*, not when it is an empty string — so a blank prompt would silently override the default and leave the server with **no STUN servers**, which breaks connectivity for any pair that is not on the same LAN. Wiring the public list explicitly removes the failure mode and one thing to get wrong during setup. |
| 2026-10-22 | 7 | **PWA manifest points at the existing SVG favicon.** `apps/web/public/manifest.json` referenced `/icon-192.png` and `/icon-512.png`, neither of which exists in `public/`. | A deployed site would 404 on both and Chrome would reject the manifest's icon set. Referencing `favicon.svg` with `sizes: "any"` removes the 404s; PNG icons remain a polish item, noted in the README's limitations. |
| 2026-10-22 | 7 | **Flagged (not fixed): `CORS_ORIGINS` is not enforced.** `apps/signaling/src/createServer.ts` ends its CORS `origin` callback with `callback(null, true)` and the Socket.IO server uses `origin: true`. | Recorded for a future hardening pass before any public launch. Leaving it permissive keeps local/LAN development working; changing it now is out of scope for the deployment task. |
